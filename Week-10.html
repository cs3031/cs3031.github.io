Week 10: Processor Design, Register Transfer Logic & The Gajendra-1 Architecture

1. Processor Design Fundamentals & Architecture Models

Building a general-purpose processor requires transforming isolated combinational and sequential logic components into an integrated system capable of executing programs stored in memory.

  ┌─────────────────────────────────────────────────────────────┐
  │                      PROCESSOR SYSTEM                       │
  │                                                             │
  │  ┌──────────────┐       ┌──────────────┐     ┌───────────┐  │
  │  │ Register     │◄─────►│ Arithmetic   │◄───►│ Control   │  │
  │  │ File (Memory)│       │ Logic (ALU)  │     │ Logic     │  │
  │  └──────┬───────┘       └──────┬───────┘     └─────┬─────┘  │
  └─────────┼──────────────────────┼───────────────────┼────────┘

  ┌─────────────────────────────────────────────────────────────┐

  └─────────────────────────────────────────────────────────────┘

Key Processor Design Concepts

  1. The Interfacing Problem: An Arithmetic Logic Unit (ALU) performs primitive operations (e.g., addition). The processor’s primary hardware complexity lies in the interfacing circuit—the data routing logic that fetches operands from memory, passes them to registers, routes them to the ALU, and stores the results back.

  2. Hardware vs. Software Emulation:

  • Native Hardware: Dedicated logic circuits embedded directly in the ALU (e.g., a hardware multiplier).

  • Software Emulation: Executing complex operations via software algorithms built from primitive hardware instructions (e.g., performing multiplication \(X \times Y\) by executing repeated addition in a controlled loop).

  1. Memory Organization Models:

  • Von Neumann Architecture: Uses a single, unified memory block for storing both program instructions and application data.

  • Harvard Architecture: Uses physically separate memory modules and data paths for instructions (Program Memory) and operands (Data Memory).

ISA vs. Microarchitecture

The connection between computer hardware and software relies on two abstraction layers:

 ┌───────────────────────────────────────────────────────────────┐
 │               SOFTWARE (High-Level Code / C / Python)         │
 └───────────────────────────────┬───────────────────────────────┘
                                 │ Target Compiler
                                 ▼
 ┌───────────────────────────────────────────────────────────────┐
 │  INSTRUCTION SET ARCHITECTURE (ISA) - The Software Contract   │
 └───────────────────────────────┬───────────────────────────────┘
                                 │ Hardware Implementation
                                 ▼
 ┌───────────────────────────────────────────────────────────────┐
 │    MICROARCHITECTURE - The Underlying Physical Hardware       │
 └───────────────────────────────────────────────────────────────┘

  • Instruction Set Architecture (ISA): The abstract programmer-facing contract (or API) defining supported instructions, register sets, addressing modes, and machine code formats.

  • Microarchitecture: The specific physical hardware realization of an ISA on silicon. A single ISA can be implemented by multiple different microarchitectures.

2. Register Transfer Logic (RTL) & Bus Architectures

The Interconnect Problem (\(O(N^2)\) Wiring Complexity)

Connecting \(N\) registers directly using dedicated point-to-point lines requires quadratic hardware scaling. For \(N\) \(k\)-bit registers, pairwise directional links require \(N(N-1)\) multiplexed channels, creating severe physical wiring congestion.

Common Bus Architecture & Tri-State Buffers

To resolve wiring congestion, modern processors use a Common Bus—a single shared parallel data highway. Access to the bus is controlled using Tri-State Buffers.

Tri-State Buffer Logic

       Input (A) ───────►[▶]───────► Output (B)
                          ▲
                          │
                     Enable (EN)
Enable (\(EN\)) Input (\(A\)) Output (\(B\)) State Description
0 \(X\) Hi-Z High Impedance: Electrically disconnects the output pin from the bus.
1 \(0\) 0 Logic Low: Drives logic \(0\) onto the bus line.
1 \(1\) 1 Logic High: Drives logic \(1\) onto the bus line.

CRITICAL BUS RULE: Exactly ONE component may drive (write to) the bus at any given clock cycle. If two components attempt to output conflicting voltage levels (\(0\) and \(1\)) simultaneously, a short circuit occurs. However, multiple components can read from the bus concurrently.

Step-by-Step Register Swap Execution over a Common Bus

Swapping contents between Register \(X\) (\(Reg_X\)) and Register \(Z\) (\(Reg_Z\)) using a temporary Register \(Y\) (\(Reg_Y\)) requires three sequential clock cycles:

Cycle 1: Reg_X ──► Common Bus ──► Reg_Y (Temp)
Cycle 2: Reg_Z ──► Common Bus ──► Reg_X
Cycle 3: Reg_Y ──► Common Bus ──► Reg_Z

Control Word Configuration for Swap Sequence

Clock Cycle Active Operation \(Mem_{out}\) \(Mem_{in}\) \(X_{out}\) \(X_{in}\) \(Y_{out}\) \(Y_{in}\) \(Z_{out}\) \(Z_{in}\) Control Word (Hex)
\(T_1\) \(Reg_Y \leftarrow Reg_X\) 0 0 1 0 0 1 0 0 0x44
\(T_2\) \(Reg_X \leftarrow Reg_Z\) 0 0 0 1 0 0 1 0 0x12
\(T_3\) \(Reg_Z \leftarrow Reg_Y\) 0 0 0 0 1 0 0 1 0x09

3. The Gajendra-1 Processor Architecture

The Gajendra-1 CPU is an 8-bit, non-pipelined, multicycle processor design (inspired by the SAP—Simple As Possible—architecture).

Core Component Specifications

  1. Common Data Bus: 8-bit parallel bus linking all functional blocks.

  2. General-Purpose Registers:

  • Register A (Accumulator): 8-bit primary working register. Primary implicit source and destination for ALU operations.

  • Register B & C: 8-bit auxiliary general-purpose working registers. Register C connects directly to output display LEDs.

  1. Gajendra ALU: 8-bit combinational logic unit performing Addition (\(A + B\)) and Subtraction (\(A - B\)).

  2. Program Counter (PC): 4-bit up-counter holding the memory address of the next instruction. Automatically increments after fetching.

  3. Memory Address Register (MAR): 4-bit latch holding target memory addresses issued to RAM.

  4. System RAM: \(16 \times 8\)-bit (16 Bytes) unified memory storing both instructions and data. Addresses range from 0x0 to 0xF.

  5. Instruction Register (IR): 8-bit register holding the current opcode and operand byte fetched from RAM.

  6. Status Register (Flags):

  • Zero Flag (\(Z\)): Set to \(1\) if the last ALU computation resulted in 0x00.

  • Carry Flag (\(C\)): Set to \(1\) if the last ALU operation generated an arithmetic carry/overflow.

  1. CPU Controller / Timing Signal Generator: Ring-counter based state machine generating multi-cycle control words every clock pulse to coordinate data movement.

4. Instruction Formats & Real-World ISA Comparison

Gajendra-1 8-Bit Instruction Encoding

Gajendra-1 uses a single 8-bit (1-byte) instruction word format:

 ┌───┬───┬───┬───┬───┬───┬───┬───┐
 │ 7 │ 6 │ 5 │ 4 │ 3 │ 2 │ 1 │ 0 │
 ├───┴───┴───┴───┼───┴───┴───┴───┤
 │  4-Bit Opcode │ 4-Bit Operand │
 └───────────────┴───────────────┘

  • Bits [7:4] — Opcode: Specifies 1 of up to 16 native operations (\(2^4\)).

  • Bits [3:0] — Operand: Specifies a 4-bit Memory Address (0x0 to 0xF) or a 4-bit Immediate Constant (\(0\) to \(15_{10}\)).

ISA TRADE-OFF: Because only 4 bits are allocated for immediate constants, Gajendra-1 can only execute immediate loads up to \(15_{10}\) (0x0F). Loading larger values (e.g., LDI 77) is impossible directly; such constants must be pre-stored in RAM and loaded via memory instructions (LDA).

Real-World Case Study: Atmel AVR ISA (ATmega328P)

Unlike Gajendra-1’s 8-bit format, commercial microcontrollers like the Atmel AVR (powering Arduino systems) use 16-bit instruction words and feature 32 general-purpose 8-bit registers (\(R_0 \dots R_{31}\)).

Example 1: Calculating Machine Code for LDI R23, 14

  • Instruction Definition: LDI Rd, K (Load 8-bit constant \(K\) into Register \(R_d\), where \(d \in [16..31]\)).

  • AVR Opcode Format: 1101 KKKK dddd KKKK

  • Target Values:

  • Destination Register: \(R_{23} \implies d = 23 - 16 = 7_{10} = 0111_2\)

  • Immediate Constant: \(14_{10} = 0000 1110_2 \implies K_{high} = 0000_2, K_{low} = 1110_2\)

Step-by-Step Bit Assembly:

  1. Opcode Prefix: 1110 (0xE)

  2. \(K_{high}\) (Bits 11–8): 0000 (0x0)

  3. \(d\) (Bits 7–4): 0111 (0x7)

  4. \(K_{low}\) (Bits 3–0): 1110 (0xE)

\[\text{Assembled Binary: } 1110 \quad 0000 \quad 0111 \quad 1110_2\]

\[\text{Final Machine Code: } \mathbf{0\text{x}E07E}\]

Example 2: Calculating Machine Code for MOV R7, R25

  • Instruction Definition: MOV Rd, Rr (Copy \(R_r\) into \(R_d\)).

  • AVR Opcode Format: 0010 11rd dddd rrrr

  • Target Values:

  • Destination (\(R_d = R_7\)): \(7_{10} = 00111_2 \implies d_4=0, d_3=0, d_2=1, d_1=1, d_0=1\)

  • Source (\(R_r = R_{25}\)): \(25_{10} = 11001_2 \implies r_4=1, r_3=1, r_2=0, r_1=0, r_0=1\)

Step-by-Step Bit Assembly:

\[\begin{array}{rcccc} \text{Format Bits:} & \text{0010 11}r_4d_4 & d_3d_2d_1d_0 & r_3r_2r_1r_0 \\ \text{Substituted Bits:} & 0010 \quad 1110 & 0111 & 1001_2 \\ \text{Hex Blocks:} & \text{0x2} \quad \text{0xE} & \text{0x7} & \text{0x9} \end{array}\]

\[\text{Final Machine Code: } \mathbf{0\text{x}2E79}\]

5. Gajendra-1 ISA & Data Flow Execution

Gajendra-1 Complete Instruction Set (ISA)

Mnemonic Opcode (Hex) Operand Format Hardware Operation Description
NOP 0x0 None None No operation; delays execution by 1 cycle.
LDA 0x1 4-bit Addr \(Reg_A \leftarrow \text{RAM}[\text{Addr}]\) Loads byte from RAM address into Accumulator.
STA 0x2 4-bit Addr \(\text{RAM}[\text{Addr}] \leftarrow Reg_A\) Stores Accumulator byte into RAM address.
LDI 0x3 4-bit Const \(Reg_A \leftarrow \text{Constant}\) Loads 4-bit immediate constant (\(0-15\)) into Accumulator.
ADD 0x4 4-bit Addr \(Reg_A \leftarrow Reg_A + \text{RAM}[\text{Addr}]\) Adds RAM contents to Accumulator.
SUB 0x5 4-bit Addr \(Reg_A \leftarrow Reg_A - \text{RAM}[\text{Addr}]\) Subtracts RAM contents from Accumulator.
MOV 0x6 Reg Specs \(Reg_{dst} \leftarrow Reg_{src}\) Transfers data between internal registers.
JMP 0x7 4-bit Addr \(\text{PC} \leftarrow \text{Addr}\) Unconditional jump; overrides PC.
JNZ 0x8 4-bit Addr If \(Z == 0, \text{PC} \leftarrow \text{Addr}\) Conditional jump; branches if Zero flag is clear.
HLT 0xF None Halt Clock Freezes PC and stops processor execution.

The Fetch-Decode-Execute Micro-operation Sequence

Every instruction in Gajendra-1 executes across a standardized multi-cycle sequence.

                  FETCH PHASE (Common to ALL Instructions)
  T1: PC ──► Common Bus ──► MAR       (Load RAM Address)
  T2: PC ──► PC + 1                   (Increment Program Counter)
  T3: RAM[MAR] ──► Common Bus ──► IR  (Latch Instruction Byte into IR)
                                 │
                                 ▼
                     DECODE & EXECUTE PHASE
  T4: Controller decodes IR[7:4] Opcode
  T5-T6: Execute specific register/ALU/RAM transfers

Complete Program Walkthrough: Emulating Multiplication via Software

Because Gajendra-1 lacks a hardware multiplier, multiplication (\(X \times Y\)) is performed by executing repeated additions controlled via the JNZ instruction.

Assembly Algorithm (\(3 \times 4 = 12\))

  • RAM[0xE]: Pre-stored value \(X = 3\)

  • RAM[0xF]: Pre-stored value \(Y = 4\) (Loop Counter)

  • RAM[0xD]: Pre-stored constant \(1\) (for decrementing counter)

; Address | Mnemonic   | Machine Code | Micro-operation Action
; ----------------------------------------------------------------------
  0x0     | LDI 0      | 0x30         | Reg_A = 0 (Initialize Sum)
  0x1     | STA 0xC    | 0x2C         | RAM[0xC] = 0 (Store Sum in Product cell)
  0x2     | LDA 0xC    | 0x1C         | Reg_A = Current Sum
  0x3     | ADD 0xE    | 0x4E         | Reg_A = Reg_A + X (Add 3)
  0x4     | STA 0xC    | 0x2C         | Update Product cell RAM[0xC]
  0x5     | LDA 0xF    | 0x1F         | Reg_A = Loop Counter Y
  0x6     | SUB 0xD    | 0x5D         | Reg_A = Reg_A - 1 (Decrement Counter)
  0x7     | STA 0xF    | 0x2F         | Save updated Loop Counter Y
  0x8     | JNZ 0x2    | 0x82         | If Counter != 0, Branch back to 0x2
  0x9     | HLT        | 0xFF         | Product Complete (RAM[0xC] = 12)

6. Executive Summary & Quick Reference

  1. Common Bus Optimization: Reduces interconnection wiring complexity from \(O(N^2)\) to a single shared highway using Tri-State buffers.

  2. Bus Contention Rule: Only one functional unit can output to the bus at a time (\(EN_{out} = 1\)), but multiple units can read simultaneously.

  3. Gajendra-1 Specifications: An 8-bit multicycle CPU featuring a 4-bit PC, 4-bit MAR, 16-byte RAM, 3 general registers (\(A, B, C\)), and an 8-bit instruction format (4-bit Opcode + 4-bit Operand).

  4. Instruction Fetch Sequence: All instructions execute a common 3-cycle fetch phase: \(\text{PC} \to \text{MAR} \implies \text{PC}++ \implies \text{RAM}[\text{MAR}] \to \text{IR}\).

  5. Software Emulation: Missing hardware logic units (like multipliers) are implemented through assembly algorithms utilizing conditional branching instructions (JNZ).
